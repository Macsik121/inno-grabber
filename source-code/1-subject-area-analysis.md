# InnoGrabber . Анализ предметной области



\*InnoGrabber - Innovation Campus materials downloader\*



\*Цель:\* Данный документ содержит в себе идеи по реализации Innovation campus materials downloader. Нужно будет проанализировать идеи и уточнить подходы. Данное приложение представляет собой скрипт, который должен будет добывать информацию по курсу, чтобы не скачивать все материалы вручную. Я хочу, чтобы скрипт снимал все материалы с сайта курса innovationcampus.ru. У меня есть доступ к самим курсам, надо только написать скрипт, чтобы автоматизировать эту работу. Предположим я захожу под своим логином на innovationcampus.ru и мне отображаются все доступные мне курсы. Дальше, я нажимаю на курс, информацию с которого хочу забрать, и дальше в дело вступает скрипт.



\*Идеи по написанию скрипта:\*

На странице курса отображается плитка с разделами, которые покрывает курс. Примерная структура каждого курса: Страница курса -> Глава/Модуль -> материал(презентация/теория/тест/лабораторная/задание/вопросы) -> переход по ссылке -> получение информации. У материалов есть оглавление: отдельный html-элемент на странице с ссылками, указывающими путь дальше по материалу. Все, кроме презентации имеют такое. Презентация - сплошной .pdf файл. У всего остального из перечисленного есть оглавление(или, например, навигация по тесту, но суть та же). Контент с ссылок на оглавление тоже надо будет собирать.



Сам скрипт должен открывать каждую плитку по отдельности и открывать каждую ссылку с материалом в ней. Переходит по ссылке -> сканирует всю страницу и вычисляет, где какой элемент -> забирает материалы. Это может быть слишком сложно, есть ли способ проще? Если это надёжнее, то выберем его.



Скрипт должен смотреть на страницу и искать нужные элементы, чтобы получить ссылки по всем материалам. Затем перейти по ней и забрать нужную информацию.



Логика скрипта при переходе на страницу:

1\. Если на странице только ссылка на .pdf файл с презентацией или теорией, то пускай открывает его и скачивает.

2\. Если на странице текст с картинками и видео, то пусть:

\- копирует текст последовательно и загружает в текстовый файл. также указывает названия сохранённых картинок и встреченных видео по ходу сканирования страницы

\- сохраняет картинку, если встречает её, и в текстовом файле указывает в том месте, где её встретил имя файла с которым же и сохраняет её

\- скачивает видео, переходя по ссылке. по идее ссылка должна быть на какой-нибудь сайт, с которого можно будет скачать видео

3\. Если страница не подходит ни под один из этих вариантов, то пускай в текстовый файл записывается информация о том, что страница является необычной.



Ввод: я сам захожу на нужную страницу курса и скрипт начинает работу. Информация о странице, где и какой элемент, известно заранее. Или можно вычислять по содержимому элементов?



Вывод:

\- markdown file с информацией о всех собранных файлах с курса. здесь можно пометить необычные, которые встретились

\- папка с текстовыми файлами, содержащими информацию о материале курса. В случае, если материал текстовый

\- папка с картинками от каждого материала

\- папка с видео от каждого материала

\- структура должна быть такая: общая папка с названием курса(сохраняется в корне проекта, рядом со скриптом) -> папка с названием раздела -> папка с названием материала -> текстовый файл с названием материала + папка с картинками + папка с видео ИЛИ пдф файл, если он там один.
